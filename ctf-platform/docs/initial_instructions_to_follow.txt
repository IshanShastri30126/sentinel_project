## 1. Project Specifications & Requirements

### A. System Architecture & Integration
*   **Direct Site Modification:** The CTF platform will be built directly inside Ishan's existing portal codebase/architecture .
*   **User Roles (4 Roles):** Student (Participant), Judge/Examiner, Question Setter, and Admin.
*   **Cross-Domain Auth & Synchronized Session Management:** 
    *   Implement OAuth 2.0 / OIDC flow using short-lived JWTs/session tokens stored in `HttpOnly`, `SameSite=Strict` cookies.
    *   Use a centralized **Redis token revocation blacklist** so that logging out on either Ishan's portal or the CTF platform immediately revokes access globally.

### B. Concurrency Control & Real-Time Engine 
*   **Scale Target:** Must handle 150+ concurrent active users seamlessly without database locks or freezing.
*   **Real-Time Presence:** Use **Redis Distributed Locks with atomic Time-To-Live (TTL)** keys alongside **WebSockets** to display live status (`"This question is currently being solved by [User]"`). If a browser drops or crashes, the lock auto-expires via TTL.
*   **Database Integrity:** Implement **Optimistic Concurrency Control (OCC)** at the database layer (PostgreSQL/MongoDB versioning) for flag submissions—NEVER use heavy pessimistic database locks (`SELECT FOR UPDATE`).

### C. Live Admin Interruption System
*   **5-Second Freeze Pop-Up:** When an admin modifies a question or hint live during an active competition, trigger a global WebSocket broadcast to active users.
*   **UI Modal Behavior:** Display a mandatory 5-second full-screen pop-up ("Question changed/modified. Please review."). Users cannot interact with the page for 5 seconds. Provide "Cancel" and "Go To Question" action buttons.

### D. UI/UX & Design Rules
*   **Color Palette:** Strictly **Green and Black** theme. Absolutely NO Red/Black palette .
*   **Styling & Components:** Avoid repetitive, generic AI-generated card layouts. Use modern React UI libraries (Aceternity UI, Animate UI, Untitle, or Flora) and catchy title typography (such as Aura fonts).
*   **Loading Performance:** Use skeleton loading and React Suspense to fetch questions lazily in micro-batches (4 at a time).
*   **Clean Direct Execution Layout:** Keep the UI focused solely on competition execution. 

### E. Code Standards & Git Protocol
*   **Mandatory File Header:** The very first line of EVERY code file MUST contain:
    `// Created: [YYYY-MM-DD] | Modified: [Details of changes]`
*   **Documentation-First:** Define SRS, System Architecture, Design.md, and Schema specifications with explicit technology versions before writing feature code.
*   **Git Discipline:** Structure local commits systematically per micro-chunk. Keep repository links private.
